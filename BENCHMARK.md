## What is measured

Five configurations, each adding one hop to the one before it:

| Configuration | Path |
|---|---|
| `direct` | client → PostgreSQL |
| `haproxy` | client → HAProxy → PostgreSQL |
| `prism_plain` | client → HAProxy → PG-Prism (plaintext) → PostgreSQL |
| `prism_tls` | client → HAProxy → PG-Prism (TLS termination) → PostgreSQL |
| `pgbouncer` | client → HAProxy → PgBouncer (`application_name_add_host`) → PostgreSQL |

Two workloads:

- **`select`** — `pgbench -S`, one persistent connection per client. Isolates
  per-statement forwarding cost.
- **`connect`** — `pgbench -S -C`, reconnecting for every transaction. This is
  where the handshake lives: PROXY header, startup parse, `application_name`
  rewrite, and for `prism_tls` a full TLS handshake, paid per transaction.

Method: at least 30 s of discarded warmup and 120 s measured per run, three
repetitions, configurations shuffled within each repetition, percentiles taken
nearest-rank from `pgbench --log` per transaction.

## Sanity checks

*Not yet run.*

The harness fails the run — non-zero exit, no publishable output — if any
configuration measures faster than the configuration it sits behind by more than
the noise floor. A proxy cannot be faster than what it forwards to. If that
happens, the measurement is wrong, and the correct response is to find the error,
not to publish the number.

## Reading this honestly

Three things to keep in mind when the tables are filled in:

1. **The `connect` numbers are the interesting ones and the least flattering.**
   Per-statement forwarding is cheap. A handshake is not, and `prism_tls` pays
   for a TLS negotiation on every transaction.
2. **`pgbouncer` is not a like-for-like comparison.** It is a pooler; under
   `session` pooling with a warm pool it is doing something structurally
   different from a per-connection sidecar. It is in the table because it is the
   closest available alternative, not because the row is a fair fight.
3. **A proxy adds latency. That is the trade.** The question this benchmark
   answers is how much, not whether. Any reading of these numbers that concludes
   the proxy is free is a misreading.
